# Step 4: Persona-Style Rewriting

## Overview

Step 4 rewrites a random subsample of original complaints into each of the 36 persona styles. This is the **matched-guise experiment**: by changing only the linguistic style while preserving all factual content, we create controlled pairs where the only variable is writing style. Any subsequent differences in remedy decisions (Step 5) can be attributed causally to linguistic style rather than complaint content.

**Source:** `src/experiment.py` → `_step_4()` (lines 1028–1077), `_summarize_step_4()` (lines 1079–1155)
**Prompts:** `src/prompts.py` → `PERSONA_REWRITE_SYSTEM`, `PERSONA_REWRITE_USER`, `format_persona_rewrite_user()`
**Schema:** `src/schemas.py` → `PersonaRewriteResponse`

---

## Causal Sample Selection

Not all complaints are rewritten — only a configurable subsample:

```python
n_sample = max(1, int(len(self.complaints) * self.causal_sample_pct))
sample = rng.sample(self.complaints, n_sample)
```

| Parameter | Default | Effect |
|-----------|---------|--------|
| `--causal-sample-pct` | 0.10 | 10% of complaints → e.g., 500 out of 5,000 |

With 500 base complaints × 36 personas = **18,000 rewrites per model**. The subsample uses a seeded random sample (`self.seed`, default 42) for reproducibility.

---

## The 36-Persona Grid

Each complaint is rewritten into all 36 combinations of the four causal dimensions:

| Dimension | Values | Count |
|-----------|--------|-------|
| Age | young (25–35), old (65+) | 2 |
| Geographic | urban, suburban, rural | 3 |
| Education | high_school, college | 2 |
| Socioeconomic | low, middle, high | 3 |

**Total:** 2 × 3 × 2 × 3 = 36 persona styles

The grid is generated by `generate_persona_grid()` in `src/schemas.py` (line 31) and stored as `PERSONA_GRID`. Each persona is labelled by `persona_label()` as `{age}_{geographic}_{education}_{socioeconomic}` (e.g., `young_urban_college_high`).

Gender and ESL are excluded from causal rewrites because they are estimation-only dimensions (see [Step 1](step-01-persona-estimation.md)).

## LLM Prompt Design

### System Prompt

The system prompt frames the LLM as a **linguistic style transfer specialist**:

```
You are a linguistic style transfer specialist. Your task is to rewrite a complaint while:
1. PRESERVING all factual content, allegations, and requested outcomes exactly
2. CHANGING ONLY the linguistic style to match how a person with a specific
   demographic profile would naturally write

The rewritten complaint must contain the exact same information and allegations,
just expressed in a different voice.
```

### User Prompt

The user prompt specifies the target persona and inserts the original complaint:

```
Rewrite the following complaint in the linguistic style typical of someone
with this demographic profile:

- Age: {age_value} ({age_description})
- Geographic setting: {geo_value} ({geo_description})
- Education level: {edu_value} ({edu_description})
- Socioeconomic status: {ses_value} ({ses_description})

ORIGINAL COMPLAINT:
{narrative}

Respond with a JSON object:
{
  "rewritten_complaint": "The full rewritten complaint text",
  "style_changes_made": ["list", "of", "linguistic", "changes", "you", "made"]
}

CRITICAL RULES:
1. Do NOT change any facts, amounts, dates, names, or allegations
2. Do NOT add or remove any claims about bank errors
3. Do NOT change the requested outcome or remedy
4. ONLY change vocabulary, sentence structure, tone, and communication style
```

### Design Choices

- **Fact preservation rules**: Four explicit prohibitions prevent the LLM from altering complaint substance, ensuring the matched-guise control holds
- **Style-only changes**: The prompt constrains changes to vocabulary, sentence structure, tone, and communication style
- **Self-documentation**: The `style_changes_made` field forces the LLM to articulate what it changed, providing an audit trail
- **Demographic descriptions**: Natural-language descriptions (e.g., "25-35 years old") guide the LLM toward appropriate style markers without prescribing specific vocabulary

## Response Schema

The `PersonaRewriteResponse` Pydantic model validates the LLM output:

```python
class PersonaRewriteResponse(BaseModel):
    rewritten_complaint: str
    style_changes_made: List[str] = Field(default_factory=list)
```

| Field | Type | Description |
|-------|------|-------------|
| `rewritten_complaint` | string | Full rewritten complaint text |
| `style_changes_made` | list of strings | Linguistic changes the LLM made |

No coercion validators are needed — both fields accept free text.

## Execution

### Request Construction

For each model, complaint, and persona combination:

```python
for c in sample:
    for persona in PERSONA_GRID:
        plabel = persona_label(**persona)
        user_prompt = format_persona_rewrite_user(
            c.narrative,
            persona["age"], persona["geo"], persona["edu"], persona["ses"],
        )
        req = LLMRequest(
            request_id=LLMRequest.new_id(),
            case_id=c.case_id,
            model=model,
            task="persona_rewrite",
            prompt_system=PERSONA_REWRITE_SYSTEM,
            prompt_user=user_prompt,
            expected_schema=PersonaRewriteResponse,
            variant=plabel,
        )
```

The `variant` field stores the persona label, linking each rewrite to its intended persona.

### Batch Execution

Requests are executed concurrently via `llm.execute_batch()` and validated via `_check_batch_results()` with timeout retry and failure rate checks.

### Result Storage

Successful responses are stored as `PersonaRewrite` dataclass objects:

```python
PersonaRewrite(
    case_id=resp.case_id,
    model=resp.model,
    original_narrative=orig.narrative,
    persona_label=req.variant,
    rewritten_narrative=p.rewritten_complaint,
    style_changes_made=p.style_changes_made,
)
```

Results are accumulated in `self.persona_rewrites` for use in Step 5.

## Manipulation Check: Persona Re-Estimation

After rewriting, `_summarize_step_4()` (lines 1079–1155) validates that the intended persona markers were successfully embedded by **re-estimating personas** on the rewritten text using the same prompts and schema as Step 1.

### Process

1. For each model, take all persona rewrites
2. Send each rewritten narrative through the persona estimation pipeline (Step 1 prompts)
3. Parse the estimated persona back into dimension values
4. Compare estimated dimension values to the intended persona

### Match Accuracy

Per-dimension match accuracy is logged:

```python
for dim in CAUSAL_DIMS:
    correct = sum(1 for intended, est in matched
                  if getattr(est, dim) == intended[dim])
    rate = correct / len(matched)
    logger.info("    %s match: %d/%d (%.1f%%)", dim, correct, len(matched), rate * 100)
```

For example:
```
  Model: gpt-4o-mini (18000 re-estimates)
    age match: 16200/18000 (90.0%)
    geographic match: 14400/18000 (80.0%)
    education match: 15300/18000 (85.0%)
    socioeconomic match: 13500/18000 (75.0%)
```

High match rates (typically >70%) confirm that the rewriting successfully embedded recognisable persona markers. Lower rates for socioeconomic status are expected, as SES markers are subtler than age or geographic markers.

### Distribution Logging

The summary also logs the estimated persona distribution across all rewritten complaints, broken down by all 6 estimation dimensions (including gender and ESL), to check whether the rewriting introduced unintended demographic signals.

## What a Rewritten Complaint Looks Like

A complaint rewritten into the `old_rural_high_school_low` persona style would transform:

**Original (neutral style):**
> I am writing to dispute a charge of $45.00 on my account. The charge was applied on March 15 and I did not authorize this transaction. I request an immediate reversal.

**Rewritten (old, rural, high school, low SES):**
> I'm writing about this $45 charge that showed up on my account March 15th. I didn't say they could do that and I need them to put it back. We can't afford to have money taken out like that.

The factual content (amount, date, allegation, requested outcome) remains identical. Only the vocabulary, sentence structure, tone, and communication style change.
