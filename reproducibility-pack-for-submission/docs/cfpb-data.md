# CFPB Consumer Complaint Data Documentation

## Data Source

This project uses the **Consumer Financial Protection Bureau (CFPB) Consumer Complaint Database**, a public dataset of consumer complaints about financial products and services submitted to the CFPB.

- **Publisher**: Consumer Financial Protection Bureau (U.S. Government)
- **Website**: https://www.consumerfinance.gov/data-research/consumer-complaints/
- **API endpoint**: https://www.consumerfinance.gov/data-research/consumer-complaints/search/api/v1/
- **Socrata dataset ID**: `s6ew-h6mp` (hosted on `data.consumerfinance.gov`)
- **Local file path**: `data/complaints.csv`

Complaints are published after the company responds or after a 15-day disclosure period. Narratives are opt-in: consumers must consent to have their complaint text published. The CFPB applies a personal information scrubbing process (CFPB narrative scrubbing standard 2023-05) before publication.

## Data Cleaning and Filtering

The data pipeline applies the following steps sequentially (implemented in `src/data_loader.py`, function `load_and_clean()`):

### Step 1: Text Normalisation

Collapse all whitespace sequences (spaces, tabs, newlines) into single spaces and strip leading/trailing whitespace.

```python
re.sub(r"\s+", " ", text).strip()
```

### Step 2: Narrative Length Filtering

Retain only complaints with narratives between **300 and 1,500 characters** (inclusive). This removes stub complaints that lack substance and overly long texts that may exceed model token limits.

### Step 3: English Language Detection

Use **fasttext** (`lid.176.ftz` model) for batch language detection, with **langid** as a fallback if fasttext is unavailable. Only complaints classified as English (`lang == "en"`) are kept.

### Step 4: ASCII Character Ratio Filter

Calculate the ratio of ASCII characters to total characters. Complaints with an ASCII ratio **below 0.85** are removed. This filters out narratives with excessive non-ASCII content that may indicate non-English text missed by language detection.

### Step 5: Null Value Handling

Missing values in `product` and `issue` columns are filled with `"Unknown"` and cast to string type.

### Step 6: Deduplication

Generate a Blake2b hash (`digest_size=16`) of each narrative. Drop rows with duplicate hash values, keeping only the first occurrence.

### Step 7: Repetition Filter

Filter out degenerate repetitive narratives (e.g. the same phrase repeated hundreds of times). Complaints with a unique-word ratio **below 0.20** are removed.

```python
unique_words = len(set(words)) / len(words)
# Keep only if >= 0.20
```

### Step 8: Redaction Filter

The CFPB replaces personal information with `XXXX` sequences. Complaints where the ratio of `X` characters to total characters exceeds **0.20** (20%) are removed, as heavily redacted narratives cause token-limit issues in downstream LLM processing.

### Step 9: Identifier Generation + Category Assignment

1. Assign a deterministic `case_id` to each remaining record (seeded RNG for reproducibility)
2. Extract `year` from `date_received`
3. Map products and issues to category groupings (`product_category`, `issue_category`)
4. Exclude product × issue pairs dominated by non-bank actors (Credit Reporting × Credit Report Errors, Debt Collection × Debt Disputes)
5. Compute issue severity scores

### Step 10: Stratified Sampling

Proportional stratified sampling by `product_category | issue_category` bucket:

1. Create a bucket column: `product_category | issue_category`
2. Calculate proportional allocation per bucket: `k = max(1, round(bucket_fraction × n))`
3. Sample `k` records from each bucket without replacement
4. Last bucket receives the remaining allocation

Default target sample size is **5,000** complaints.

## Data Quality Limitations

The following limitations should be considered when interpreting results:

1. **Not statistically representative** - The CFPB explicitly states "this database is not a statistical sample of consumers' experiences in the marketplace."
2. **Unverified narratives** - Complaints are published without verification; allegations are treated as consumer opinion.
3. **Size bias** - Larger companies receive disproportionately more complaints due to customer volume.
4. **Product concentration** - Approximately 80% of complaints relate to credit reporting.
5. **No direct demographics** - The CFPB collects no demographic data from complainants. Only limited tags ("Older American", "Servicemember") are available.
6. **Misclassification** - Fraud and scam issues are frequently unlabeled or miscategorized.
7. **Temporal lag** - A 15-day publication delay plus processing time means data is not real-time.
8. **Selection bias** - Data is skewed toward consumers willing and able to file formal complaints.
